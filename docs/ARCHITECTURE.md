# Architecture

Markdown Leaflet is one Rust desktop binary built with `iced`. Its main boundary is between filesystem/document rules and the UI event loop.

```text
path or file dialog ──→ folder scan ──→ folder browser ──→ selected path
                            │                                 │
                            └── config                         ▼
                                                       Document::open/reload
                                                         │           │
                                                         ▼           ▼
                                                   Markdown items   outline
                                                         └─────┬─────┘
                                                               ▼
                                                            iced view

click / key / timer ──→ Message ──→ State::update ──→ state or Task ──→ State::view
```

## Modules

| Module | Responsibility |
| --- | --- |
| `main.rs` | Declares modules and starts the app. |
| `app/` | The `iced` application. `state.rs` owns `State` (with `NavState`, `MenuState`, `FindState`) and `State::input_scopes`; `message.rs` the `Message` enum; `update/` the transitions, one handler module per area (files, menu, navigation, keyboard, find, gutters, layout) routed from `update/mod.rs`; `update/keyboard.rs` is only the `iced`-key-to-`keymap::Chord` adapter and the `Command` dispatch, not the keymap table itself; `subscription.rs` timers, key events, and window resizes; `view/` pure rendering (toolbar, menu, dialog, gutters, folder panes, panels, document). |
| `actions.rs` | `MenuAction`, shared by the in-window and native menus. |
| `domain/keymap.rs` | The keybinding table: `Command`, `Scope`, `Chord`, `Binding`, `defaults()`, and `resolve(scopes, chord)`. The single source for dispatch, tooltip and menu-row chord hints, the Help dialog, and the README shortcut table. |
| `domain/document.rs` | Reads a Markdown file, splits off a leading frontmatter block (`domain/frontmatter.rs`) before parsing render items, builds its outline, reloads after a disk change, and formats inspector values. |
| `domain/frontmatter.rs` | A leading `---`/`---` YAML block: `split` pulls it off the raw source (byte-0 detection only; a block that never closes, or fails to parse, is left untouched so the file renders exactly as it would without this module) and `parse` turns it into `Frontmatter`'s ordered `(String, FrontmatterValue)` fields for the Details panel. `FrontmatterValue` (`Scalar`/`List`/`Map`) is the boundary — nothing outside this module touches a `serde_saphyr` type directly. |
| `domain/stats.rs` | Counts words, characters, lines, links and images in a document's source for the inspector. |
| `domain/outline.rs` | Extracts headings and visual indices from parsed Markdown items. |
| `domain/walk.rs` | Scans a folder for supported Markdown extensions using `ScanRules`, which also lists `.txt` files when `[files] show_text` is on (`ScanRules::lists`); owns the default ignored directories and the extension tables. |
| `domain/folder.rs` | Builds the folder tree, filters paths, expands selected ancestors, and chooses the next keyboard selection. |
| `domain/workspace.rs` | Opens a file or folder into a `Workspace` (scan, selection restore, failures) and keeps a visible selection across rescans. |
| `domain/find.rs` | ASCII case-insensitive in-document search ranges. |
| `domain/selection.rs` | Preview text selection: `BlockId`, `Position`, and `Selection` range math, select-all, and `word_at` for double-click. Offsets are bytes into a leaf's text. |
| `domain/links.rs` | Decides whether a clicked link names a Markdown file inside the open folder (relative, absolute, or `file://`; fragment and query ignored). `Message::LinkClicked` opens such a file in the same window and hands every other link to the OS. It also classifies a link to an existing Markdown file *outside* the root (`external_markdown_target`, returning the file's real path with symlinks resolved), and `may_open_externally` allow-lists what else may go to the OS (web, `mailto:`, and safe local document types inside the root). Containment is checked on resolved paths, so a symlink cannot lead out of the folder. |
| `domain/minimap.rs` | The minimap's pure geometry: `Geometry` (scale, viewport slider, click-to-offset, bars) over `Block`s measured from the preview, `BlockKind::of` mapping a Markdown item to how it is drawn, `current_heading` and `Marks` (find-match items, the active one, and the heading the reader is in), and `line_count`/`line_length` for the text lines drawn inside a tall bar. Scale is capped so a short document stays a small sketch. |
| `domain/history.rs` | Session-only back/forward stack of visited documents with each one's scroll offset; `visit` drops forward entries and ignores a repeat of the current document. |
| `domain/images.rs` | Which `![alt](url)` targets can be shown: `resolve` accepts a relative, absolute, or `file://` path to a supported image (PNG, JPEG, GIF, WebP, BMP, SVG) inside the open root and refuses everything else; `image_urls` walks items (lists and quotes, not table cells); `decode` reads a file within size and dimension limits. |
| `domain/create.rs` | The new-item/rename draft, name validation, default names, and creating a blank Markdown file or a folder holding one, or renaming a file. |
| `domain/editors.rs` | The editors offered by Open With. |
| `domain/recent.rs` | Loads and saves recent file/folder paths in the OS configuration directory. |
| `config/` | Loads user settings, parses palette overrides to plain RGB (`palette.rs`), supplies `ScanRules`, and preserves TOML while saving appearance. It does not import `iced` or `theme`. |
| `layout/` | Pure responsive rules with no `iced` dependency. `breakpoint.rs` holds every width threshold and the `Breakpoint`, `ToolbarDensity`, and `MenuLayout` enums; `spacing.rs` the spacing scale (8 px `UNIT`, 4 px `HALF`) that every layout gap is built from; `budget.rs` the gutter width limits and preview budget; `typography.rs` the golden-ratio line height, which grows with the preview's text measure (`LayoutPlan::text_measure`) and reaches φ at φ⁷ em; `plan.rs` `plan(Viewport, PanelIntent) -> LayoutPlan`, which says whether each gutter is `Hidden`, `Docked`, `Overlay`, or (Files only, in compact windows) a top `Strip` and at what width. Also owns `GutterSide`. |
| `gutter/` | `GutterState` (the user's visibility and active-side intent, each gutter's tab, widths, drag, cue fades, card slides) with `LeftTab`, `RightTab`, and `ResizeDrag` (`mod.rs`); `Tween` and `Easing`, the clock-injected animation primitive both the cue fade and the slide use (`motion.rs`); width anchors, drag deltas, and snap selection (`resize.rs`). |
| `platform/` | OS integration: file pickers (`dialogs.rs`), the `Opener` trait for links and editors (`opener.rs`), the macOS menu bar (`native_menu.rs`), which bridges events to `MenuAction`, and Finder open requests (`macos_open.rs`, macOS only): it adds `application:openURLs:` to winit's application delegate, which AppKit calls for a double-click, Open With or a Dock drop, and queues the paths that the 100 ms native-menu tick opens through `Message::OpenRecent`. It is the only module that uses `unsafe` (`unsafe_code` is `deny` in `Cargo.toml`, allowed in that one file). Other platforms use the in-window menu in `app.rs`. |
| `ui/` | Rendering helpers with no application state: `theme.rs` (styles, palettes, `Appearance::from_config`), `fonts.rs` (the bundled Source Sans/Serif/Code faces and `body(FontChoice) -> Font`), `icons.rs` (inline SVG), `images.rs` (`ImageStore`: URL → file → load state `Slot` for the open document), `press_area.rs` (captures the exact pointer x on a divider press), `find_viewer.rs` (markdown viewer that highlights find matches and selections, and harvests each leaf's plain text), `selectable_text.rs` (one selectable text leaf), `selection_area.rs` (blank-click clear and drag auto-scroll over the preview), `context_area.rs` (opens a context menu on right-click), `slide.rs` (`SlideLayer` positions a gutter card without squeezing it; `Collapse` takes a fraction of a child's width), `title_search.rs` (`TitleSearch` lays the toolbar's title and search field out in one slot; its `split` function is the tested math), `focus_watch.rs` (`FocusWatch` reports a text field's focus changes, which iced's `text_input` does not publish), `locate_heading.rs` (scroll offset of a heading or match), `measure_blocks.rs` (reads each `document-find-{i}` block's top and height in content coordinates), and `minimap.rs` (the strip widget: bars, viewport slider, press and drag). |

Errors are typed per module (`DocumentError`, `ConfigError`, `OpenError`, `SelectionIssue`) with `thiserror`; `State` renders them into an error banner.

## Event flow

`State::update` is the decision point for user actions and timer messages. Opening a file or folder goes through `Workspace::open_file` or `Workspace::open_folder`, which scan Markdown paths and restore the selection; `State::show_workspace` applies the result. `domain/folder.rs` renders and navigates the tree. Selecting a file opens a `Document` inside folder mode. The left gutter shows Files; the right gutter has Outline and Details tabs. `State::view` translates the current mode into widgets; it should not own navigation rules.

Subscriptions poll the selected document for changes every 600 ms and an open folder every 3 seconds. File dialogs run through `Task`s. The app also uses the OS to open links or another editor. Configuration and recent items are the only app-owned persistent files.

The config file is loaded at startup. `Appearance::from_config` combines the chosen mode with built-in light/dark colors and optional palette overrides. View → Reload Theme re-reads only the theme into `State`; it leaves the current folder scan rules in place until restart. Menu actions become `Message::MenuAction` and transition in `State::update`. On macOS, `native_menu.rs` owns the platform menu and polls its event receiver; it installs the menu on the first poll tick, because winit replaces the main menu while launching; the rest of the app uses `iced` menus. About and shortcuts are in-app dialogs.

## Folder state

`Mode::Folder` also represents a file opened directly. Its root is the file's parent folder. `NavState::cursor` drives the highlighted row independently of the selected `Document`, so arrow keys can highlight folders and move quickly through files without opening every intermediate file. A 160 ms delayed task opens the final file; its generation token discards superseded tasks. `open_file` includes the selected path even when the normal folder scan excludes it; `Message::FolderScanned` preserves that path while it exists. Keep these paths in sync when changing file discovery or recent-item restore.

## Responsive layout

`State::viewport` holds the window width, plus one latch: once two gutters are allowed (from 1120px) they stay allowed down to `TWO_GUTTERS_HOLD` (32px) narrower, so a window edge hovering at the threshold does not flicker the second gutter; `Viewport::resized` applies it and the preview-width budget is still checked separately. A startup task reads it (`iced` reports no size until the first resize) and a `window::resize_events` subscription keeps it current through `Message::WindowResized`. Nothing stores derived layout: `State::layout_plan()` runs `layout::plan` on the viewport and `GutterState::intent()` whenever a view or handler needs it. Intent (what is open, which side is active, stored widths) lives in `GutterState` and survives resizes; the plan (what is shown, where, at what width) is recomputed. The toolbar, menus, panes, and the toggle and drag handlers all read the same plan, so no view compares a width itself; add or move a threshold only in `layout/breakpoint.rs`.

Below 720 px (`Compact`) Files becomes a mini-nav strip above the preview (`Placement::Strip`, built by `State::mini_nav`) and the right gutter overlays the preview, so both can be open together; from 720 px (`Medium`) at most one docks; from 1120 px (`Wide`) two dock if each stays within the 420 px preview minimum. The toolbar and Open Recent submenu switch shape at 900/560 and 490 px.

## Gutter state

`GutterState` and `State::layout_plan()` are shared verbatim between `Mode::Folder` and `Mode::Welcome` — neither has any mode-specific logic. `State::folder_panes` and `State::welcome_panes` (both in `view/folder_panes.rs`) are the two call sites that turn one `layout_plan()` into a `PanelBody` (content plus floating overlay cards); `welcome_panes` is the simpler of the two, with no right-gutter content and no `left_tab` branch — Welcome's left panel content is always `State::recent_panel`, since there's no Files tab before a folder is open (issue #70).

`GutterState::right_tab` chooses Outline or Details. The right toolbar button only reveals or hides that gutter; the tab buttons and Ctrl+Page Up/Down (`Command::CycleRightTab`) change it. `GutterState::left_tab` chooses Files or Recent the same way, cycled by Ctrl+Shift+Page Up/Down (`Command::CycleLeftTab`), except the left tab buttons double as that gutter's own toggle: `Message::SelectLeftTab` sets the tab and reveals the gutter, but closes it instead if it is already open on the requested tab — there being no separate left-gutter toggle button in its header the way the right gutter has one. Welcome ignores `left_tab` (it has no Files option), and never opens the right gutter at all. `Message::TogglePanel` hides a gutter the plan shows and reveals one it does not, in either mode. `sidebar_visible` and `inspector_visible` remember whether each gutter is open, and each gutter has an independently adjustable width; because `GutterState` is one shared field on `State`, these persist across a Welcome ↔ Folder mode switch exactly like any other field would. When both are open but only one fits, `GutterState::active` decides which is shown. A stored width shrinks at render time to keep the preview minimum and returns when the window widens. The width budget includes each 8 px well. The 8 px resize target and its 2 px edge line are overlaid on the card's own inner edge and border (`State::with_resize_strip`, a `Stack` over the card and its margins) and consume no layout width. Their position comes from `layout::budget::edge_spans`, the same spans a test checks (the line's outer edge is the card's outer edge, so nothing lies between line and border); placing the strip against the footprint instead would leave it a margin away from the card. The drag records the exact pointer x and initial width on press; global movement applies a directional delta and clamps to the feasible preview width. Release snaps to a nearby eligible anchor, then clears the drag. Opening a folder or searching brings Files forward in the left gutter.

Each open gutter renders as a floating card, not a panel boxed into the row below the toolbar: `State::view` stacks it (`iced::widget::Stack`) over the toolbar-plus-content block, so the card's top can bump into and visually float over the toolbar while its bottom still lands clear of the content row's own bottom edge by one `OUTER_MARGIN`, the same gap it keeps above the footer — one `Stack` gives both for free, with no separate height bookkeeping for "how tall is the footer." The in-window menu row (non-macOS) sits outside this stack, above it, always visible and clickable — it is chrome in its own right, the same way the native macOS menu bar is, not a surface the nav is meant to float over. `app/view/folder_panes.rs::folder_panes` returns a `FolderBody` (the content row, still reserving `width + gutter_overhead()` per docked side so the preview doesn't run under a card, plus each side's optional card) instead of drawing the cards inline; `State::view` is what stacks them. `app/view/gutters.rs::gutter_card` builds a side's card with an optional header zone — the gutter's own toggle, and each gutter's tab capsule (`State::gutter_tabs`, which takes a side, a list of chips, and the active tab, so both gutters' headers build their capsule from the same code) — divided from the body below it the way the footer divides from the content above it. `docked_margin`/`overlay_margin` give the padding around the card: a docked card keeps `budget::OUTER_MARGIN` clear of the window's own edge, the topbar above, and the footer below — its border is never flush with any of them — and a narrower `budget::INNER_MARGIN` on the edge that carries the resize handle; the two horizontal margins sum to exactly `gutter_overhead()`, so nothing drifts out of step with the card's actual footprint. An overlaid card (compact windows) keeps the full outer margin on every side instead, since there is no resize handle. The toolbar grows its own top padding by that same `OUTER_MARGIN` (`State::toolbar`), so its content lines up with a header's despite the header now sitting `OUTER_MARGIN` lower than the window's top edge. A gutter's header controls live in the card while it is open (`State::left_nav_header`, `State::right_gutter_header`) and move into the topbar while it is closed (`State::sidebar_toggle`, `State::right_gutter_toggle`); the toolbar's own slot for that side collapses to the bare toggle alone while the gutter is open. Back/Forward are document history, not nav-specific, so they stay in the toolbar alongside the toggle even while the nav is closed, not just inside its header. A header row and the toolbar's own primary row use matching padding and are top- rather than center-aligned, and every control in either (icon buttons, the search field, Open With, either gutter's tab capsule) is fixed to the same `TOOLBAR_CONTROL_HEIGHT` rather than its own natural size, so a control that moves between the toolbar and a header (the gutter toggle) lands at the identical pixel either way, instead of drifting with whichever row happens to hold a taller sibling that session. A toolbar toggle and the View menu checkmarks still reflect the gutter that is actually shown at the current width. `GutterState::hovered` and `drag` set the target for each transient resize cue, whose animated opacity `GutterState` holds, and a 16ms subscription runs only during a 130ms transition. The line, boxed grip, and adjacent edge share this opacity, leaving the card's normal border intact.

Opening or closing a gutter slides its card from or to the window edge (180 ms; `Slide` in `gutter/mod.rs`). `Slide` holds only a running tween, so a card is fully in place whenever it is idle and the plan shows it, and state set directly (a restored workspace) needs no slide state. `TogglePanel`, `SelectRightTab`, and `SelectLeftTab` start a slide in `update/gutters.rs` (`slide_out` before closing, `reveal_with_slide` when opening); `LayoutPlan` is never given a fractional state. A card the plan has already hidden is still drawn from `Slide::held` (its last placement and width) until it is gone, which is also what keeps the preview's reserved width until the card has left, so the Markdown reflows once per toggle rather than every frame. `State::card_slot` picks the plan's card or the held one, and `State::slid_card` wraps it in `ui/slide.rs::SlideLayer`, which lays the card out at its natural width and only then moves it to its slid position within the layer. (iced's `pin` gives its child `max - position` as available width, so a card sliding toward the right edge was squeezed and its text rewrapped.) It is always a `SlideLayer`, at rest too, so the widget tree has one shape and the nav list keeps its scroll offset. The toolbar's own copy of the buttons a gutter replaces (toggle, history, and Open on the left; font, copy path, and toggle on the right) does not slide with it: while a slide runs, `State::toolbar` leaves the left cluster out and `State::toolbar_ghost` draws it where the closed toolbar puts it, dimmed by a toolbar-coloured cover (`State::faded`; iced has no widget opacity). The right cluster instead stays in its row, dimmed the same way and wrapped in `ui/slide.rs::Collapse`, which reports a fraction of its natural width (with its leading gap inside it): removing it outright would shift every right-anchored control, the search field included, by its width at the start of a slide and again at the end. `GutterState::toolbar_fade` derives the dimming from the card's position, reaching fully hidden at 60% of an arrival and returning over the last 60% of a departure, so it reverses with the card. The rest of the toolbar (the search field and the right-hand actions) moves with the card: `State::toolbar` moves its padding on each card's side with `slide_progress`, through `budget::toolbar_padding`: away it is the toolbar's own edge padding, in place the content rests one `CONTENT_GAP` (8 px) past the card's visible border (tested against `edge_spans`, on either side), and between the two the field glides along the card's edge instead of jumping. The left cluster's width stays in the row while its card slides, as a hidden copy wrapped in `Collapse` (its visible copy is the ghost below), so the title beside it glides too; the right cluster stays visible in its row and collapses. The ghost layer is always in the stack, empty when idle, so the cards keep their widget state. The compact `Strip`, a window resize (`WindowResized` snaps every slide), a drag, and startup do not animate, and `[animation] enabled = false` makes every slide instant. One 16 ms `AnimationTick` subscription serves cues and slides and runs only while either is moving.

## Toolbar title and search

In the full-width toolbar the open document's name (`State::toolbar_title`, an `EllipsisText` with a tooltip while elided) and the search field share one slot (`ui/title_search.rs::TitleSearch`): the title at its start, the search at its end. `split(available, title_natural, expand, ..)` is the whole layout rule: at rest the search keeps `SEARCH_WIDTH` and the title takes what is left up to `TITLE_MAX_WIDTH`; at `expand = 1` the title is a third of its width and the search takes the rest. The widget measures the title's real width itself, so nothing is estimated. `State::search_expand` (a `gutter::motion::Eased`) drives `expand`. It targets 1 or 0 on `Message::SearchFocused(bool)`, which the `FocusWatch` around the search field publishes whenever its focus differs from `State::search_focused`: the watch asks the field through a widget `Operation` after every event, so a click, Tab, the focus shortcut, and a click elsewhere are all caught without `text_input` having a focus event. The shared 16 ms `AnimationTick` advances it and runs only while it moves. With `[animation] enabled = false` it snaps. Escape: `FocusWatch::on_escape`, set only while the field holds text, claims Escape before the field sees it, publishing `Message::SearchCleared` (the × button sends the same) and leaving focus where it is; with an empty field it is not set, so Escape reaches the `text_input`, which blurs itself, and `FocusWatch` reports the blur. `State::input_scopes` adds `Scope::Search` while `search_focused`, with `Command::ClearSearch` bound to Escape so Help lists it and the keymap resolves it ahead of Find and Dismiss. The two-row and stacked toolbars have no title and no expansion; the field already fills its row there.

## Text selection

Each rendered heading, paragraph, code line, and image caption is a **leaf**, wrapped by `SelectableText`, which hit-tests the pointer with its own shadow `Paragraph` (the inner `rich_text`'s is private) and reports gestures as `SelectionEvent`s. A `BlockId` is the top-level item index plus the leaf's render order within it. `FindViewer` paints the selection by slicing span backgrounds, as it does for find matches. `State::leaves` holds each leaf's plain text, harvested by running the same `Viewer` pass when a document loads or reloads (table cells cannot be walked from outside `iced::widget::markdown`); copy, Find Selection, and the Linux primary selection all read it through `State::selected_text`. A press on text is captured by its leaf, so `SelectionArea` treats an uncaptured press as blank space. Inside the scrollable, a leaf sees scroll-translated and, past the viewport, levitating cursors; it lands the cursor while dragging so the head follows the pointer during auto-scroll.

## Images

`Document::open` only parses text. After a document opens or reloads, `State::load_images` (`update/images.rs`) asks `ImageStore::plan` to resolve each image URL with `domain::images::resolve`, keep entries whose file mtime is unchanged, and return the rest; each becomes a `Task` that decodes on a blocking thread and replies with `Message::ImageLoaded(path, mtime, result)`. A result for a file that has since changed or left the document is dropped. `FindViewer::image` draws the slot: the image (raster or SVG, shrunk to the column by `ContentFit::Contain`), a loading box, or a failure box with the alt text and reason. It always registers the alt text as a leaf, shown or not, so `BlockId`s and find counts do not shift as images load. Right-clicking a drawn image opens its own menu (`Message::OpenImageMenu`, built by `image_entries` in `update/context_menu.rs`): Open Image hands the file to the OS, and Copy Image Path puts it on the clipboard. Copying the pixels is not offered, because iced's clipboard carries text only. Remote URLs are never fetched. Limitations: images inside table cells are not loaded, only a Markdown change triggers a reload, and the scroll position restored by Back/Forward may land off while images above it are still loading.

## Plain-text files

With `[files] show_text = true` (default off) the scan also lists `.txt` files. `Document::open` gives one `DocumentKind::Text`: `raw` is the file, with no parse, outline or frontmatter. `State` forces `DocumentView::Source` for it, and `toggle_document_view` and the toolbar's source button are inert, so `ui::source_view::render_source` draws it (monospace, `plain` = no Markdown coloring and no line numbers) and selection, copy and Find reuse the Source leaf numbering. The toggle is a "Show Text Files (.txt)" row, checked and reading "Hide Text Files (.txt)" while text files are listed (it has no icon, since a row draws its checkmark in the icon's place), at the foot of every nav right-click menu (file, folder and blank space; appended in `OpenContextMenu`) (`Message::ToggleShowTextFiles`, `update/files.rs`): it saves through `Config::save_show_text` and rescans at once. A text file that is open when the setting goes off stays open until the reader navigates away. New files are still Markdown only; a rename of a text file keeps `.txt` (`create::validate_as`), and `folder_blocker` counts listed text files as allowed. A link to a `.txt` file inside the folder opens in-app only while the setting is on (`local_markdown_target`'s `include_text`); otherwise it goes to the OS.

## Frontmatter

`Document::open` splits a leading `---`/`---` YAML block off the raw text with `frontmatter::split` before anything else sees it, so `markdown::parse`, `extract_outline`, and `DocumentStats::of` all run on the body only; `Document::raw` still keeps the whole file, frontmatter included, for Copy and Select All. `split` only ever looks at byte 0 (after an optional BOM): a `---` anywhere else in the file is ordinary Markdown. A block that never closes, or closes but fails to parse as YAML (`frontmatter::parse`, built on `serde_saphyr`), is left entirely alone — `Document::frontmatter` is `None` and the body passed downstream is the original, unsplit text, so the file renders exactly as it would with this module absent. A parse failure also sets `Document::frontmatter_error`, which `State::footer` shows as a small warning glyph with a tooltip (`frontmatter_status` in `app/view/mod.rs`) rather than blocking the document or the error banner. `Frontmatter::title()` (a non-empty top-level `title:` scalar) overrides the file name in both `State::title` (the window title) and `toolbar_title`, through `Document::display_title`. `app/view/panels.rs::inspector_panel` renders a FRONTMATTER section between FILE and CONTENT when `Document::frontmatter` is `Some` and non-empty: a scalar or a flat list of scalars is one row; a map, or a list holding anything but scalars, becomes a label row (a field/item count stands in for a value) followed by its own fields or items, each indented one more guide line than its parent, the same nesting `outline_sidebar` uses for headings. Reloading re-runs `Document::open` end to end, so frontmatter needs no reload handling of its own. Scope: YAML only (`---`), display only, no write-back; `+++` (TOML) or other delimiters are left as ordinary Markdown.

## Context menus

A view opens a menu by wrapping an element in `ContextArea`, which reports an uncaptured right-click with its window position as `Message::OpenContextMenu(ContextTarget, Point)`. `update/context_menu.rs` builds the entries for each `ContextTarget` as a plain function, so adding a menu means a new variant and a builder; entries carry the `Message` they send, and `ContextMenuPick` re-dispatches it through `State::update`. `view/context_menu.rs` renders `MenuState::context` with the shared rows in `view/menu_list.rs` (also used by the Linux menu bar), flipped to stay inside the window. A child can add detail before the menu opens, as a preview leaf does with `ContextLinkPressed` for a right-clicked link.

`State::open_buttons` is a single combined Open control, identical in both modes: it follows `State::history_buttons` (plain, separate Back/Forward buttons, Folder only) in the nav header, or in the toolbar while the panel is closed (`State::left_cluster`, shared by `toolbar_leading`, `toolbar_ghost`, and the Full-density toolbar's mid-slide branch). On Welcome it sits in `State::welcome_panel_header` instead of `State::left_nav_header`, beside a plain "Recent" text label rather than the Files/Recent tab capsule — there is no separate Recent control anywhere in either mode (issue #70). It follows the same shape as Theme/Font: a plain left-click `on_press` for the primary action (open a file), and the button wrapped in `ui/anchor_area.rs::AnchorArea::on_right_press`, which reports the button's bounds on a right-click, plus `State::with_dropdown_mark`'s corner triangle. Its right-click reports `Message::OpenFileOrFolderDropdown(Rectangle)`; `update/context_menu.rs::open_entries` fills a `ContextMenu` with the two choices it collapses, the same way `new_entries` does for `State::new_item_button`'s `Message::OpenNewDropdown`. `new_item_button` is the nav header's "+" control, open-panel only (no closed-toolbar copy): left-click `Message::NewMarkdownFile`, right-click the same dropdown `nav_footer`'s button used to open, now positioned under this button instead of flipped upward. Every one of these tooltips, and every other toolbar/gutter tooltip, goes through `State::maybe_tooltip` rather than `iced::widget::tooltip` directly: it builds the tooltip only when `self.menus.context` is `None`, so a hovering tooltip never sits over a dropdown or right-click menu that just opened.

The Theme and Font buttons (`State::theme_button`, `State::font_button`) are cycle buttons: a click sends the existing `MenuAction::Appearance(next)` or `MenuAction::PreviewFont(next)`, with `next` from `AppearanceChoice::next` or `FontChoice::next`, so they save and report errors like the menu bar. A right-click opens a dropdown through `AnchorArea::on_right_press`, which publishes `Message::OpenThemeDropdown` or `OpenFontDropdown` with the button's bounds; `update/context_menu.rs` (`theme_entries`, `font_entries`) builds the checked list. `with_dropdown_mark` in `view/toolbar.rs` overlays the corner triangle that marks them.

The nav has its own menus (`ContextTarget::NavFile`, `NavFolder`, `NavBlank`): each file and folder row is wrapped in a `ContextArea`, and the list as a whole opens the root menu from the space the rows leave. A sticky New button under the list (`State::new_button`) opens the same create entries above itself (`Message::OpenNewDropdown`). Naming flows through a draft: `NavState::draft` (a `domain::create::NewItem`) holds the name being typed, for a new file or folder or for a rename (`NewItem::rename`), and nothing touches disk until `create::commit_item`. `domain/create.rs` also owns the pure `validate_item` rules (blank, forbidden characters, Windows reserved names, `.md` appended, other extensions rejected, clashes; a rename may keep or re-case its own name). New Folder creates the folder with a blank `Untitled.md` because the tree lists only folders holding Markdown. `update/new_item.rs` starts, edits, commits, and cancels the draft: Enter commits (and opens a new file), a press outside the field commits a valid name or discards an invalid one through a subscription live only while a footer draft exists, and Escape is handled ahead of the keymap in `update_keyboard`, which also limits the keyboard to Global bindings while drafting. A rename repoints the list, cursor, `History::rename`, and reopens the document if it was the open one. `view/new_item.rs` draws the field: a new item's in the nav footer above the New button (`State::nav_footer`); a rename's in the row being renamed (`rename_row`, from `folder_file_row` and the folder rows); either becomes `Dialog::NewItem` when the Files gutter is not docked. Folders can be renamed or trashed only when everything inside is Markdown (`create::folder_blocker`; `.DS_Store`, `Thumbs.db`, and `desktop.ini` are ignored); the right-click menu shows those rows disabled with an (i) icon whose tooltip names the offending file (`ContextEntry::Item::info`), and F2 or Delete on such a folder shows the same reason in the error banner. The rule is checked again at commit and at confirm, since the folder may change meanwhile. A folder rename or trash rebases or drops every file, the cursor, expanded folders, and history entries under it (`create::rebase`). F2 renames and Delete or Ctrl/⌘ Backspace trashes the file or folder the nav highlights (`Command::RenameItem`, `DeleteItem`; `State::keyboard_nav_target`). Delete (`update/delete.rs`) asks in `Dialog::ConfirmDelete`, then `Opener::trash` moves it to the system Trash (the `trash` crate), so it is recoverable. The New button uses `theme::create_button`, which lights up in the full accent on hover, a style reserved for buttons that create. Show in Finder, Open in New Window (a second instance started on the path), and the default-app hand-off go through `Opener`.

## Navigation history

Opening a folder or file (a Recent item, the file picker, a command-line path, a Finder open, or the external-link dialog's Open Containing Folder) is asynchronous. `State::request_open` takes a `domain::workspace::OpenRequest`, bumps `NavState::open_generation`, records it in `NavState::opening` (the footer shows "Opening “name”…"), and runs `OpenRequest::run`, the scan and document read, on a blocking worker through `LoadedWorkspace`, like `LoadedDocument`. The result returns as `Message::WorkspaceOpened`; a result from an older generation is dropped, and `State::finish_open` either shows the workspace or reports the error with a retry. The current view stays until then. A command-line path is opened from `boot`, after the window exists. Tests cannot run a `Task`, so they finish the pending open with `State::complete_pending_open`. An external Markdown link (`update/external_link.rs`, `view/external_link.rs`) is handled by `Message::LinkClicked` before the OS hand-off. With the default `[links] external_markdown = "ask"` it sets `NavState::pending_external` and opens `Dialog::ExternalLink`, which offers Open Containing Folder (`State::open_file`, so the file's folder becomes the workspace and history resets), Open as External Document (`FileSelected`: the open folder and its file list are untouched), or an editor from `domain::editors::EDITORS` via `Opener::open_with`. The "Always do this" checkbox (`NavState::external_always`) saves the chosen action through `Config::save_external_link_action`, a `toml_edit` update that keeps comments and other keys; a remembered `folder` or `document` is applied without a dialog. View → Ask About External Links (`MenuAction::AskAboutExternalLinks`) restores asking, and View → Reload Theme re-reads the `[links]` table. Dismissing the dialog clears the pending file. Images and relative links inside an external document still resolve against the open folder, so they may not show until the external-documents group (#33) lands.

`NavState::history` is a `History` of documents shown this session. Every user navigation (`FileSelected`, which the file list, arrow keys, and in-folder links all send) first reads the preview's scroll offset with the `ReadScroll` operation, then loads. `finish_load` runs when the load succeeds: it stores that offset on the entry being left, then either adds an entry (`visit`) and starts at the top, or, for Back/Forward (`HistoryBack`/`HistoryForward` in `update/history.rs`), moves to `NavState::history_target` and scrolls to that entry's saved offset. The index moves only after the load, so a missing file shows the error banner and leaves history intact (`fail_load` still steps onto the entry so the reader can keep going). Reloads never touch history; opening a workspace or closing the document clears it. Triggers: toolbar buttons, Alt+←/→, ⌘[ / ⌘], and mouse Back/Forward buttons (`subscription.rs`). Trackpad swipes are not delivered by iced/winit.

## Where to change behavior

- Markdown parsing or reload: `domain/document.rs`; heading extraction: `domain/outline.rs`; frontmatter detection and parsing: `domain/frontmatter.rs`.
- Folder discovery or ignored directories: `domain/walk.rs` (`ScanRules`); `config/` supplies the user overrides.
- Folder ordering, search, or arrow selection: `domain/folder.rs`, then check the `app/view/folder_panes.rs` call site.
- A new interaction: add a `Message` in `app/message.rs` and handle it in the matching `app/update/` module; keep `app/view/` focused on presentation.
- A new or changed keyboard shortcut: `domain/keymap.rs`'s `defaults()`, not `app/update/keyboard.rs`. Dispatch, tooltips, menu rows, the native macOS accelerators, the Help dialog, and the README table all follow from that one table; the README has a drift test.
- Window-width behavior or a new breakpoint: `layout/breakpoint.rs` and `layout/plan.rs`, with a test; views take the `LayoutPlan`.
- The preview body font: `FontChoice` and `[preview]` in `config/`, faces in `assets/fonts/` registered from `ui/fonts.rs` in `app::run`; `render_markdown` sets `markdown::Style::font` and `FindViewer::with_font` so selection measures with the drawn face. A new preset needs its faces in `BUNDLED` and a `MenuAction::PreviewFont` row in both menus.
- Appearance: `ui/theme.rs`, `ui/icons.rs`, and [DESIGN.md](DESIGN.md).

The useful seam is whether a rule can be exercised without creating an `iced` window. Keep such rules in the small modules and leave widget composition in `app.rs`.

## Minimap

`[preview] minimap` (default off) reserves a 72 px strip just left of the preview's scrollbar, which stays on the pane's right edge, and draws it only when the document scrolls. The strip is a `stack!` layer over the scrollable (a spacer keeps it clear of the 10 px scrollbar), and `TextSetting::reserve_right` pads the text so it never runs under the strip. The strip is a raised panel, so it casts a shadow onto the text to its left. The strip stays in the layout, blank, while a document loads or fits the window, so switching documents never changes the preview's width or widget tree (which reflowed the text and flashed). The preview's scrollable publishes `PreviewScrolled(Viewport)` on scroll, resize, and content-height change (iced notifies only when the viewport differs, and not at all while the content fits). `update/minimap.rs` stores the offset, viewport height, and content height in `State::minimap.geometry`; when the content height differs from the one last measured it runs `MeasureBlocks` and stores the result as `Block`s (`BlocksMeasured`), so images loading or a reflow re-measure by themselves. `view/folder_panes.rs` draws `ui::minimap::Minimap` from `Geometry::bars` and `Geometry::slider`. Pressing or dragging the strip sends `MinimapSeek(y)`, which `Geometry::offset_for_click` turns into a `scroll_to` that centres the viewport. The toggle is `MenuAction::ToggleMinimap` (toolbar button, View menu, `Ctrl/⌘ Shift M`) and persists through `Config::save_minimap`. Limitations: the strip's width comes out of the preview's, and the text measure does not account for it; a document that fits the window leaves the strip blank.
